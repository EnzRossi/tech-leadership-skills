# Idea validation: reconciliation helper

Finance head · Internal · Digital · Non-AI · Portugal

## Verdict

**Pursue the limited internal release — Confidence: high for this bounded decision.** The weakest point is whether the prototype’s performance and support burden persist in release; that is a fixable uncertainty. Reported voluntary use across all 200 eligible tasks, unchanged checked error rate, documented alternative failures and accepted ownership justify proceeding within the approved effort cap.

## The idea as a hypothesis

Finance staff can complete the eligible reconciliation workflow faster with a helper that supports the required legacy export format. The prototype supports a limited release.

## What the evidence shows

All findings below rely on supplied facts. Value and usability are supported: 10 staff chose the helper over the existing workflow and completed all eligible tasks. Median handling time fell from 20 to 8 minutes, with the same checked error rate.

Feasibility is supported for this scope by working usage and IT’s acceptance of maintenance, access and rollback ownership. Finance documented why the licensed suite and two evaluated alternatives fail a specific requirement. 

Viability is supported for the bounded step by the approved effort cap; ongoing support effort remains unquantified. The benefit is staff capacity, not demonstrated cash savings: no layoffs or reduced external spending are planned. Medians alone cannot establish aggregate hours saved. 

## Cheapest test that could change the verdict

Use the release itself as a monitored continuation with the same cohort and eligibility scope for four weeks, within the existing cap. Proposed thresholds for finance and IT to agree: continue if median handling time remains below 20 minutes, checked error rate does not rise, and work stays within the cap; pause and use IT’s rollback process if any threshold fails. Track voluntary adoption and support effort alongside these measures. Sustained regression would change the verdict.
