# AI initiative decision: Transcript prototype

Support sponsor · Evidence: explicit data-owner refusal reported in your prompt

## Recommendation

**Confidence: High.**

Do not proceed with the prototype using those customer transcripts. The data owner has explicitly refused this purpose; offline execution does not supply permission. Postpone that data-dependent work. A real backlog and willing business owner establish a plausible need, but they do not override a known access boundary.

## Decisive evidence

The support backlog and ownership are reported positive signals. Data readiness is a known blocker, not an untested concern. The team's “offline is harmless” argument addresses only one possible exposure route and does not establish authorized use.

The strongest available alternative is bounded process discovery using information already permitted for that purpose: workflow observation, approved aggregate workload measures and support-owner interviews. Deterministic routing, documentation or staffing/process changes may address part of the backlog without the denied transcript use. Their value remains untested.

## Good enough for the next stage

First establish an authorized input path. The data owner can clarify whether a narrower purpose, minimization, retention boundary or different dataset is acceptable. Do not assume that de-identification or synthetic copying authorizes transformation of the refused transcripts. Independently created synthetic examples may test mechanics if permitted, but cannot prove representative customer performance or backlog reduction.

Once permission and usable examples exist, define the actual support task and compare current handling with the strongest simpler approach. Reserve representative held-out cases, including ambiguity and costly mistakes; have qualified support staff adjudicate answers. Measure full handling and correction effort, supported answers, escalation correctness and sensitive-data exposure. Agree acceptance and stop criteria before pilot funding. The present decision authorizes none of that exposure.

## Next commitment

Proposed owner: the support sponsor together with the data owner. Produce a documented decision on permitted data and use boundaries, while completing a small process-baseline review using authorized material. Advance only with affirmative authorization and a plausible evaluation contract. If no permitted representative path exists, keep this prototype stopped and assess process alternatives.

## What could change the recommendation

An affirmative authorization for a revised design or a genuinely separate, approved dataset would remove this blocker. A technical promise that the same denied material stays offline would not. The remaining questions are what specific use is refused, whether an acceptable alternative exists, and which support task drives the backlog; none warrants bypassing the refusal.
