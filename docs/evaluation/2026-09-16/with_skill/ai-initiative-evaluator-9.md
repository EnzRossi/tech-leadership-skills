# AI initiative decision: Department agent mandate

CEO · Evidence: mandate reported in your prompt

## Recommendation

**Confidence: High that there is no investment case yet.**

No-go for building or deploying an agent on the evidence supplied. Go for a bounded problem-discovery step. A CEO mandate establishes sponsorship, but says nothing about which task benefits, whether an agent can perform it reliably or what it would cost. Do not invent a use case to make the mandate look justified.

## Decisive evidence

No workflow, user, volume, baseline, data, error consequence or accountable operational owner is identified. These are Unknown. There is also no demonstrated reason for autonomous tool use rather than a process change, deterministic automation, existing product or review-only assistant.

Doing nothing technologically is the strongest current alternative because the benefit of a new capability is unproven. That does not mean ignoring operational problems; it means identifying one before choosing a system. Agent orchestration adds permissions, retries and state-change failure modes that should earn their cost through a concrete task need.

## Good enough for the next stage

Ask departments to nominate existing expensive or error-prone workflows with permitted examples and an owner. For the most credible candidate, observe the current process and compare the strongest simpler alternative. Discovery should produce a measurable outcome, baseline, available inputs and an error boundary—not an agent architecture.

If that evidence supports a prototype, reserve representative held-out cases and agree domain-qualified judging. Evaluate whole-task completion, review effort, cost and consequential errors. For any later agent test, also verify authorized final state, repeated actions, tool failures, escalation and recovery. Thresholds must follow the actual task's risk and baseline; none can be credibly specified from the mandate alone. Keep exposure offline or review-only until the appropriate gates are met.

## Next commitment

Proposed owner: an operations leader with participating department heads. Time-box one discovery pass to the next investment review using existing staff. Deliver a short list of evidenced problems and one recommended next commitment, including “no AI” if simpler changes suffice. Advance only with meaningful need, permitted inputs, an owner and a credible comparison; stop technology-specific planning where those remain absent.

## What could change the recommendation

The strongest case for action is a recurring, costly workflow whose interpretation or prediction needs defeat simpler methods and whose risks can be contained. Three questions establish that case: which task and user; how often it occurs and what failure costs; and who owns the outcome and has permitted data? A credible answer can justify investigation or prototyping, without requiring every department to deploy an agent.
